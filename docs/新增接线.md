# 新增接线：WorkBuddy / Qoder / CodeArts / API Key

这一份只记「宿主侧新加了什么」，实现细节在各模块头部注释里。

## 一、为什么需要写进渠道包

渠道包的模型可见性是 `providerCatalogVisible()`（`vendor/channel-pack/pack.js:31102`）：

- 判据是**凭据能否解析**，不是「账号池里有没有条目」；
- `DSH_HIDE_MODELS_WITHOUT_ACCOUNT` 缺省开启，凭据解析不出来 → 整个 provider 被过滤掉。

所以任何一家新接入都必须**成对**写两件东西：

1. `ctx.credentials.set(credentialRef('<PREFIX>_ACCOUNT_<HEX>'), json)`；
2. `pool.addAccount({ id: '<provider>-<hex小写>', provider, credentialRef, ... })`。

`src/pack-inject.js` 把这两步封成一个 `injectCredential()`：id 与 ref 都由同一个 seed
派生（sha256 前 8 位），因为 `pack.js:29851` 在 `state.json` 丢失时是按 ref 名重建账号的，
自己另起一个 id 会在重建时多出一条「幽灵账号」。

## 二、WorkBuddy / CodeBuddy（本机登录态）

- 模块：`src/workbuddy/discover.js`、`src/workbuddy/store.js`
- 凭据来源：桌面端自己写的 auth 文件（**不**登录、不碰钥匙串）
  - macOS：`~/Library/Application Support/CodeBuddyExtension/Data/Public/auth`
  - Windows：`%LOCALAPPDATA%` / `%APPDATA%` 下的同名目录
  - Linux：`$XDG_CONFIG_HOME` / `$XDG_DATA_HOME`
  - 覆盖：`WORKBUDDY_AUTH_FILE`
- 落到哪个产品由凭据里的 `domain` 决定：含 `workbuddy` → `workbuddy`，含 `tencent`/`copilot` → `buddy`，其余按 `workbuddy`。
- `domain` 为空时**不写**这个字段：`pack.js:30559` 的 `pruneAccountsWithForeignDomain()`
  会把 `domain` 与产品 `apiDomain` 不一致的账号删掉，空字符串是它唯一会跳过的值。
- 路由：`GET /buddy/status`、`POST /buddy/import`

## 三、Qoder（PAT）

- 模块：`src/qoder/store.js`、`src/qoder/index.js`
- 凭据来源：面板粘的 PAT（`pt-…`）、`QODER_PERSONAL_ACCESS_TOKEN` / `QODERCN_PERSONAL_ACCESS_TOKEN`
- 区域：`global` ↔ provider `qoder`，`cn` ↔ provider `qodercn`；**没有默认区域**，缺参会抛 `REGION_REQUIRED`。
- 凭据形状（`pack.js:38619 buildQoderCredential`）：
  `{ security_oauth_token, access_token, machine_id, uid?, nickname? }`
  - `machine_id` 由 PAT 的 sha256 派生，重启后仍是同一条设备记录；
  - PAT 没有过期时间，所以不写 `expire_time`、`refreshable: false`。
- 聊天必须走 cosy 签名，签名在渠道包内用 WASM 完成（`pack.js:38946 QoderEncryptedInfer`），
  所以**不要**用裸 `Bearer` 覆盖它生成的 `Authorization`。
- 路由：`GET /qoder/status`、`GET /qoder/accounts`、`POST /qoder/accounts`、`POST /qoder/accounts/remove`、`POST /qoder/verify`
- 启动补写：`qoderSync()` 在启动 9 秒后跑一次（vault 里的 PAT 每次启动都要重新写进凭据库）。

## 四、华为云 CodeArts（OAuth2 + PKCE + DPoP）

- 模块：`src/codearts/dpop.js`、`src/codearts/store.js`、`src/codearts/oauth.js`
- 登录：`start()` 先 `listen(0)` 拿到真端口再拼授权 URL，环回回调走 `127.0.0.1`，5 分钟超时。
- 令牌落 `~/.dsh/get-it-for-free/.codearts-accounts.json`（0600，串行写队列）。
- 写进渠道包的凭据（`pack.js:34073` 只要前三件就能签名）：
  `{ access_key_id, secret_access_key, security_token, expires_at?, user_name?, user_id?, domain_id? }`
  - `refreshable: false`：渠道包自己续期需要 `code_verifier`，那份只在登录那一刻存在；
    续期由本插件负责，`getToken()` 会在快过期时先续。
- 回写节奏：启动后 12 秒一次，之后每 15 分钟一次（`getToken()` 没有过期就不碰网络）。
- 路由：`GET /codearts/status`、`POST /codearts/login`、`POST /codearts/login/cancel`、`POST /codearts/sync`、`POST /codearts/accounts/remove`

## 五、API Key

渠道包自带 OpenAI 兼容网关，密钥由它自己管：

- `loadOrCreateApiKey()`（`pack.js:65166`）：43 位 base64url，落 `~/.dsh/openai-gateway/api-key`（0600）
- `mountOpenAiGateway(ctx, pool)`（`pack.js:66886`）在 `pack.js:71195` 无条件挂载
- 面板：`GatewayCard`（`client.js`）—— 开关、复制 base_url、复制 `base_url + api_key` 配置、
  显示/隐藏/复制密钥、重新生成（没有密钥时按钮显示「生成 API Key」）、自检

## 六、与 billion-context 共存（华为云渠道）

bili 一旦拿到 CodeArts 凭据就会自己重签（`sdk-hmac-sha256`），而它重签出来的请求
华为云必拒（补尾斜杠、给部分模型加 `maas_type: benefit`），症状是「华为云整条渠道不可用」。

所以：

- 启动时做一次幂等校正：只在 `readBiliCompat()` 报告 `present && mode === 'resign' && scheme !== null`
  时改成 `passthrough`（改前自动备份），其它状态不动；
- 面板上有手动开关：`GET /bili/status`、`POST /bili/passthrough`；
- `scheme === null` 表示 bili 压根不管这类请求，不去替它新建配置。

## 七、出站净化的修正

`src/http.js` 的 `sanitizeOutboundBody()` 原来缺了渠道包里的两条指纹改写
（`pack.js:36004-36013`）：上游对「第三方 agent 提示词」做模糊匹配，那两句同时出现即回
`400 code=11128`。已补进 `TRACE_PHRASE_REWRITES`，顺序仍在品牌折叠之前。

## 十、免费池（`free:auto`）

做什么：把本插件自己的免费车道合成一行虚拟模型，按实测表现排序，失败的车道进冷却排到后面。灵感来自
dsh-model 的免费池，规则照搬它最关键的那条——**会扣钱的通道默认不进池**。

代码落点：

| 位置 | 作用 |
| --- | --- |
| `src/freepool.js` | 规则本体：`POOL_ID='free:auto'`、`POOL_CHANNEL='freepool'`；`NEVER` 集合排除 combo / 聚合 / eac / 池自身；`benchMsFor()` 冷却时长；`notePoolFailure()` / `benchedUntil()` / `clearBench()`；`poolCandidates()` 排序；`buildPoolEntry()` 能力交集；`poolStatus()` 给面板 |
| `src/adapter.js:213` | `runStream` 在 combo 分支之前拦 pool 行，把候选序列当 `runCombo` 的 chain 传下去；`:312` 只有 pool 行会 `notePoolFailure` |
| `src/core/runtime.js:105` | `rebuildCatalog()` 在真实车道合并之后、combo 之前插入池行；`:401` `poolStatus()` 直接读运行时那份 catalog |
| `index.js:1628` | `deps.freePool = { status, save, reset }`；路由 `GET/POST /free-pool`、`POST /free-pool/reset` |
| `src/store.js` | `SETTINGS_INITIAL.freePool = { enabled: true, name: '', exclude: [], limit: 8 }` |
| `client.js:4471` | `PoolCard`，文案键 `fpool.*`（中文在 `client.js` 的默认表里，紧挨 `ms.*`） |

两个坑，写下来省得再踩：

1. **`deps.pool` 已经被占用**（渠道包账号池快照，配 `GET /pool`）。新键必须叫 `freePool`，否则对象字面量
   里后写的键覆盖前一个，`/pool` 路由变成 `deps.pool is not a function`。
2. **`classifyFailure` 的 verdict 没有 `code` / `message`**（`src/route/classify.js:483`，只有
   `kind` / `scope` / `rule` / `cooldownMs`）。第一版冷却表按 `code`+`message` 正则匹配，于是 429 被当成
   「认不出来的普通错误」只罚 60 秒。现在先按 `kind` 查表，再用 `cooldownMs` 只往上顶不往下压——
   路由那个数是**重试**退避（5xx 30 秒），池要的是**降级**时长，两者不是一回事。

边界（别对外声称多了）：

- 只覆盖本插件 catalog 里的免费车道。渠道包车道（buddy / workbuddy / qoder / codearts）、豆包、MiMo 各自
  独立 `registerAdapter`，不在这个 catalog 里，进不了池；要用它们做自动挑选，仍然只有手写 combo 一条路。
- 池行与免费模型组同一个门禁（`freeChannelsEnabled`）。关掉免费组就整组不见，这是一致行为。
- 每日签到日程**不用我们另建**：`vendor/channel-pack/pack.js:62385` 的 `createAutoCheckin` 已经带了
  启动补签、失败重试预算、当天结果汇总、已关闭标记，`.start()` 在 `pack.js:62394` 被调用，`stop()` 挂在
  `ctx.effect` 上。再写一个调度器只会让两个调度器抢同一批账号去领券，风控那边看着更像脚本。
  想改首轮延迟用 `DSH_CHANNEL_PACK_AUTO_CHECKIN_DELAY_MS`。
- 冷却表是进程内内存态，重启即忘。这是有意的：它记的是「这个进程刚被谁拒过」。
