# 精简清单（t5 只读审计）

审计范围：`src/`（55 个 .js 模块）、`index.js`、`client.js`、`client 2.js`、`scripts/`。
方法：全仓 grep（`.js`/`.mjs`）+ 逐个导出名反查调用方 + import 图对照。
**本轮未修改任何文件。** 下面每条都给：位置 → 为什么是死的 → 风险等级。

风险等级定义：
- **安全**：全仓零引用、或只在本文件内自用；删了不会改变任何运行时行为。
- **需验证**：本仓零引用，但可能是外部契约（发版签名、文档承诺、第三方调用），删前要确认没有仓外消费者。
- **不要删**：看起来重复，但两份都在跑，合并要改行为。

## 1. `src/token-saver/rtk/registry.js` — 整模块零引用（安全）

- 位置：`src/token-saver/rtk/registry.js:1-57`，导出 `resolveFilter(name)`（:50）、`allFilters()`（:55）。
- 为什么死：全仓 grep `rtk/registry`、`from './registry'`、`registry.js'` 只命中它自己的 JSDoc `@module` 行（:13），没有任何 import 方。
- 被谁覆盖：`src/token-saver/rtk/autodetect.js:31-44` 直接 import 全部 12 个 filter 自己建表，`src/token-saver/rtk/index.js` 走的是 `autodetect` + `applyFilter`，`FILTERS` 常量来自 `src/token-saver/rtk/constants.js:129`。registry 那份 `REGISTRY`（:29-41）+ `ALIASES`（:44-47，rg→grep、fd→find）是 Rust `resolve_filter` 的移植残留。

## 15. 净化词表：两份实现，已经漂移（不要删，要补）

- 本仓：`src/http.js:399-444`
  - `TRACE_PHRASE_REWRITES`（`:399-404`，4 对）、`TRACE_BRAND_RE`（`:406`）、`scrubTraceString`（`:408`）、`scrubTraceValue`（`:418`）、`export function sanitizeOutboundBody(body)`（`:442`）。
  - 消费方：`src/http.js:451`（`postStreamed`）、`src/eac.js:210`、`src/cli-lane.js:1079`。
- vendored：`vendor/channel-pack/pack.js:35995-36081`
  - `HARNESS_BRAND_RE`（`:35995`）、`DSH_FINGERPRINT_REWRITES`（`:36004-36013`）、`rewriteDshFingerprintText`（`:36014`）、`neutralizeHarnessBrandText`（`:36022`）、`WEB_SURFACE_PHRASE`/`WEB_SURFACE_NEUTRAL`（`:36030-36031`）、`neutralizeWebSurfacePhrase`（`:36032`）、`DSH_IDENTITY_REWRITES`（`:36037`）、`rewriteDshIdentityPhrases`（`:36045`）、`sanitizePromptText`（`:36059`）、`neutralizeHarnessBrandValue`（`:36062`）、`sanitizeHarnessIdentityInBody`（`:36072`）。
- 关键判断：**这不是"重复"，是本仓那份是子集。** pack.js 是四段流水线（brand → fingerprint 句 → web 面短语 → identity），`src/http.js` 只有 brand + 三条短语 + 一条 `deepseek-harness` 替换，**缺 `DSH_FINGERPRINT_REWRITES`（那两条 "Tokens prefixed with @" / "identify files or directories on the host" 的指纹句）和 web 面短语那一段**。
- 也就是说：走本仓 `sanitizeOutboundBody` 的请求（`postStreamed`、eac、cli-lane）会把指纹句原样发给上游；走 pack.js 的路径才干净。这是**行为差异**，不是代码风格问题。
- 为什么不能简单合并：pack.js 是 vendored 单文件，那几个函数没有 `module.exports`，import 不进来。`src/http.js:388-398` 的注释自己承认了这点，并指到 `交接文档 §4.16`。
- 建议动作：**把 pack.js 缺的两段词表搬进 `src/http.js`**（对齐词表），并保留"改词表要两边一起改"的注释。删任一份都会让某条路径失去净化。
