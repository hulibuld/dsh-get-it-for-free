## 一、为什么按 `/api/v1` 猜一定猜不着

任务点名的 5 个候选，加上 `/api/v1` 下 7 个同义猜测，**12 个全部落空**，形态还特别骗人：

| 候选 | 结果 |
| --- | --- |
| `/api/v1/user/quota` | 200 + `text/html` 43695B |
| `/api/v1/quota` | 200 + `text/html` 43695B |
| `/api/v1/subscription` | 200 + `text/html` 43695B |
| `/api/v1/user/subscription` | 200 + `text/html` 43695B |
| `/api/v1/agent/quota` | 200 + `text/html` 43695B |
| `/api/v1/user/{credits,balance,wallet,usage,plan,membership}` | 同上 |
| `/api/v1/agent/credits` | 同上 |
| `/api/v1/user/me` | 200 + JSON，但**没有余额**：只有 `phone`/`status`/`entitlementInit.dailyLoginGrantAmount = null` |

秒悟的路由不存在时**不返回 404，而是 200 + 整页 index.html**（43.7KB）。
所以「看状态码找端点」这条路在这里是死的 —— 必须看 `content-type` 与正文形状。

## 二、真端点是怎么找到的

`https://meoo.com/` 只挂一个脚本：

```
<script src="https://g.alicdn.com/meoo/meoo-web/0.0.113/assets/index.js">
```

顺着它的动态 import 爬到 `bootstrapApp.js`（爬 400 个 chunk 落盘后 grep），里面写着：

```js
Dr = "/api/mc"
initEntitlement:  () => yt(`${Dr}/entitlement/init`)
getEntitlement: e => yt(e ? `${Dr}/entitlement/get?projectId=${e}` : `${Dr}/entitlement/get`)
getMemberEntitlement: () => yt(`${Dr}/entitlement/member/get`)
getMemberCredits:     () => yt(`${Dr}/entitlement/member/credits`)
getLedgerListAndSummary: e => nt(`${Dr}/pontos/ledger/list-and-summary`, e)
```

**额度服务独立在 `/api/mc`（monetization）下，压根不属于 `/api/v1`** —— 这是「按 v1 猜」失败的根本原因。
用真实 cookie 逐个验证：

| 端点 | 结果 |
| --- | --- |
| `GET /api/mc/entitlement/get` | **200 JSON 12079B ← 拿着真数字** |
| `GET /api/mc/entitlement/init` | 200 JSON 275B（只有 `initialized/dailyLoginSkipReason`，无余额） |
| `GET /api/mc/entitlement/member/credits` | **403** `{"error":{"code":"403","message":"当前版本不支持此接口"}}`（个人版不支持） |
| `POST /api/mc/pontos/trading/availableForTrading` | 落到 SPA 首页（这个要 POST，GET 不算数） |
| `GET /api/enterprise/credits/usage` | 403 同上（团队版功能） |

## 三、额度响应的关键字段（实测）

```json
{
  "planCode": "free", "planType": "personal", "planName": "Free 免费版",
  "activatedStartTime": "2026-11-18T00:16:38.541",
  "activatedEndTime": "9999-12-31T23:59:59",
  "benefits": [
    { "typeCode": "model_credits", "typeName": "构建使用的模型消耗", "valueType": "QUOTA",
      "quota": 66000, "used": 272, "defaultQuota": 5000, "sourceSystem": "BILLING" }
    // …另 12 条：daily_login 2000 / supabase_count 1 / upload_file_size 50MB / swarm_mode 等
  ],
  "userPointInfo": {
    "account": {
      "userId": 1874791853051708,
      "availableBalance": 65728,   ← 这才是「还剩多少」
      "frozenBalance": 0,
      "totalGranted": 66000,
      "totalConsumed": 272,
      "totalExpired": 0,
      "totalRefunded": 0
    },
    "activeGrants": [
      { "sourceType": "BOOST_PACK",   "totalInitialAmount": 50000, "totalRemainingAmount": 50000,
        "grantDetails": [{ "remainingAmount": 50000, "expiresDate": "2027-11-19T00:00:00" }] },
      { "sourceType": "SUBSCRIPTION", "totalInitialAmount": 5000,  "grantDetails": [{ "expiresDate": "2026-12-18" }] },
      { "sourceType": "DAILY_LOGIN",  "totalInitialAmount": 6000,  "totalRemainingAmount": 5728,
        "grantDetails": [{ "expiresDate": "2026-11-26T23:59:59" }] }
    ]
  }
}
```

- `availableBalance = totalGranted − totalConsumed = 66000 − 272 = 65728`，与
  `benefits[model_credits].quota − used` 完全对上，两处可互相校验。
- `activatedEndTime = 9999-12-31` 表示「永不过期」，不能直接丢给卡片倒计时。
- 有`userPointInfo`时以它为准；缺了退回 `benefits[model_credits]` 的 `quota − used`；两处都认不出**抛错**，
  绝不当 0 显示（0 会让用户以为额度用光了）。

## 四、实现（五处）

### 4.1 `src/meoo-web/session.js`

- `MEEO_WEB_APIS.entitlement = '/api/mc/entitlement/get'`（注释写明额度不在这套 `/api/v1` 下）。
- `async quota(options)`：`this.json(MEEO_WEB_APIS.entitlement, { timeoutMs: 15_000 })` → `quotaOf(body)`。
  形状对齐 `models()`：认出来的结构交出去；鉴权语义与 `json()` 一致（401/HTML → `NeedLoginError`）。
- `export function quotaOf(body)`：纯函数，返回
  `{remaining, total, used, frozen, unit:'积分', planCode, planName, expiresAt, at}`。

### 4.2 `src/meoo-web/provider.js`

- `async credits()`：`loadStore()` 取原始账号行 → **每条用自己的 cookie 建临时 `MeooWebSession`**
  查一次（并行），**不动 `session` 缓存**，所以正在跑的对话不受影响，切号也不用重建。
- 单条失败折成 `{accountId, nickname, balance:null, error}`，卡片能按账号显示原因。
- 一条账号都没有（只有 CLI token / 单份凭据）时回一条合成行 `accountId:'meoo-web'`，
  id 与卡片侧 `account.list` 合成的那行一致，号码才对得上。
- 返回形状对齐千问办公：`{accounts:[{accountId,nickname,balance:{total,unit},plan,used,total,expiresAt,error}], activeAccountId}`。

### 4.3 `index.js`

- 新路由 `GET /meooweb/credits` → `deps.meooWeb.credits()`（照 `/meooweb/accounts` 的写法）。
- 桩 `meooWebBridge.credits` → `{accounts:[], activeAccountId:''}`（通道没挂载＝没得查，不制造噪音）。
- 真桥 `credits: () => meooWeb.credits()`。

### 4.4 `client.js` —— 只动 `credits.balances` 分支

```js
case 'credits.balances': {
  let data
  try { data = await api('/meooweb/credits', { timeout: readStatus }) }
  catch (error) {
    if (isMissingRoute(error)) return { accounts: [] }   // 老宿主 404 = 没得查
    throw error                                          // 其它失败要冒上去，别伪装成「无数据」
  }
  const rows = Array.isArray(data?.accounts) ? data.accounts : []
  return { accounts: rows.map(row => ({ accountId, nickname, balance, plan, used, total, expiresAt, error })) }
}
```

`CHANNEL_CREDITS['meoo-web'] = { status: true }` **没改**（那行在 buddy-fixer 的写范围）——
不用改也生效：`loadBalances` 只判条目存在，`balanceLabel` 取不到 `unit` 会退到「剩余积分」，语义正好。

### 4.5 `scripts/probes/archive/_mw-quota.mjs`

13 个 `/api/v1` 候选（留作「猜不着」的证据）+ 4 个从 bundle 挖出来的 `/api/mc` 端点；
`user/me` 打印时脱敏手机号/邮箱；余额类字段排在配额字段前面，结论段直接指出可用端点。

## 六、待实测 / 遗留

   「剩余积分 65728」，点「刷新余额」走 `/meooweb/credits`。

   `provider.credits()` 的「每条自己的 cookie」分支**没有被真实双账号数据覆盖**，
   只有代码路径覆盖（`creditOf(accountSecret(row), …)`）。
3. `client.js` 里 `createMeooWebRpc` 的文档注释（约 3860-3868 行）还写着「上游没有余额数字，
   credits 只回一条空状态」，已过时。按 T5 划界（client.js 只许动 `credits.balances` 分支）**没有改**，
   留给 buddy-fixer 那一侧顺手更正，免得下次有人照注释又把这段改回空表。
4. `POST /api/mc/pontos/ledger/list-and-summary` 是消费流水（可做「今日消耗」），本轮没接；
   要接的话必须走 POST，且先确认真实凭据下的返回形状。
