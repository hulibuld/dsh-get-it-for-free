## 一、报障

## 二、已完成的审计（全部只读核对）

### 2.1 报错源头
`vendor/channel-pack/pack.js` `case "model.list"`（原 64366，现 64408 附近）：
`llm.listModels(req.provider)` 抛 TypeError → catch 包成「读取模型列表失败：${reason}」。
原文案只有 message 没有栈，无法定位肇事帧。

### 2.2 源码级全链路排除
- `TraeAdapter.listModels → ensureRemoteModels → RemoteCatalogGate → disabledModelsFor → providerCatalogVisible`：无裸 `.get`。
- 注册链 `registerAdapterIdempotent → wrapAdapterWithTokenLedger(Proxy) → withDeadModelPruning(Proxy)`：两层 get trap 均 `Reflect.get(target, prop, target)`，透传正确。
- 宿主 `LlmRuntime`（app.asar 逐字核对）：`adapters` 是类字段 `new Map()`；`listModels → registration(provider).adapter.listModels`；`prepareRoutes/commitRoutes` 原样存适配器不再包装；`detachedModalities` 安全。
- 运行中插件 = 工作树符号链接（`~/.dsh/profiles/desktop/node_modules/dsh-get-it-for-free → 仓库`），md5 一致，排除「半代际热重载」常驻态。
- dsh-vision-router 全部 llm/ctx/适配器包装层逐一审计（runtime-i18n-boundary / vision-tool-runtime-boundary / adapter-update-coalescer / native-image-coexistence / twin-image-capability-fallback / local-vision-stabilizer / ollama-cold-start / replay-delegation）：所有 WeakMap/Map 均模块级或闭包内正确初始化，所有 registerAdapter 拦截对非自有路由原样透传，未发现可产生 undefined.get 的路径。
- dsh-cost-meter model-labels：只读调用，带 1s 超时兜底，无包装。

## 三、裁决

源码级链路无缺陷。线上报错的剩余嫌疑（按优先级）：
1. **报错瞬间的运行时形态与当前工作树不一致**——今天 17:45/17:49 两次宿主崩溃日志证实曾有多版带语法错误的 client.js 被热加载；TRAE 报错若发生在同一窗口，可能是半代际模块的瞬时态。
2. 宿主侧某个未审计到的第三方包装在特定事件序列下改了 llm 服务形态（静态审计未找到，需运行时栈证实）。

**已落地的定位手段**：`model.list` catch 现在把完整 `error.stack` 落 `ctx.logger.warn`。
下次复现时直接看宿主日志 `[channel-pack] model.list(trae) failed:` 后的堆栈即可一帧定位。

## 四、D13 宿主 fail-loud 加固（已落地）

宿主机制（app.asar 核实）：`process.on('unhandledRejection') → report → process.exit(1)`。
任何插件浮空 fetch rejection 都炸整个宿主。今天两次崩溃：
`fatal load failure: [TypeError: fetch failed] cause ConnectTimeoutError 8.137.191.76:443 / 180:443 timeout 10000ms`。

已审计全部后台 fetch 调用点（feed/updater/outlet/qwenwork/mimo/doubao/pack 各 refresh），
绝大多数已带 catch。本轮补齐两处低危浮空点：
- `index.js` 两处 `void settleOutletWatch()` → `.catch(() => {})`（egress 开/关路径）。
- `pack.js` `primeOpencodeCapabilities` 的 `.then` 补 `.catch(() => {})`。
- `pool.listAllAccounts().then` 已有 catch，无需动。

8.137.191.76/180 为阿里云 IP，仓库/配置/asar 均无字面量，肇事 URL 未定位；
若再次崩溃，崩溃日志的 cause 栈会带上肇事模块（本轮已确保本插件所有后台路径不再贡献浮空 rejection）。
