日期：2026-11-20 · 队长只读分析产物 · 状态：已批准进任务板（T2 基座升级），全员仍暂停

参考实现：https://github.com/cv-superding/dsh-deepseek-web-login
（读了 README + src/browser-login.ts + src/browser-transport.ts；模式借鉴，代码按本仓库裁剪重写）

## 一、为什么换基座

秒悟现状（src/meoo-web/session.js / provider.js）：
- 登录态靠 `adoptBrowserCookie()` 从用户日常 Chrome 的 cookie 库文件 + Keychain 解密抄录；
- `healFromBrowser()` 自愈时再去抄一次 —— 用户浏览器里登的是哪个号插件说了不算，
  抄回来可能是另一个账号（D3b 串号的根源）；
- 多账号添加入口受限、去重弱（D3/D3a）。

deepseek-web-login 的解法：**每个账号一个独立持久浏览器 profile**。
登录窗打开就是该账号自己的登录态；「添加新账号」先清分区，「重登此账号」不清分区。
串号在物理上不可能发生，cookie 新鲜度由浏览器自己的续期机制保证。

## 二、采纳的三个模式

### 1. CDP 登录窗（替代 cookie 库抄录，作为主路）
- 拉起系统 Chrome/Edge，独立 profile 目录：`<DSH_HOME>/get-it-for-free/meoo-profiles/<accountId>/`
  （目录名 sanitize：`[^A-Za-z0-9._-]` → `_`，去前导 `.`，截 80 字符）。
- 启动参数必须 `--remote-debugging-port=0`（系统分配端口，真实端口写在
  `<profile>/DevToolsActivePort` 第一行；硬编码端口在 Windows 会撞保留区间）。
- 可见窗口让用户正常登录 meoo.com；登录完成后用 CDP `Storage.getCookies` 读全套
  cookie（含 httpOnly 的 `login_oneday_ticket`、`oneday_sid` 及两个 `.sig`），
  免 Keychain 解密、免 cookie 库文件锁。
- 捕获成功 → 写入 account-store（kind=cookie），窗口关闭。
- 旧抄录路径（chromecookie.js）保留为兜底：没有可用系统浏览器时仍可手贴 Cookie。

### 2. 自愈 = 重开同一 profile 重读（根治 D3b）
- 凭据被上游判死（401/NEED_LOGIN）时，headless 重开**该账号自己的 profile**，
  重读 cookie 再探一次 `/api/v1/user/me`。
- 秒悟刷新是 cookie 轮换：浏览器开着就会续期，profile 里的 cookie 永远新鲜，
  且不可能读到别的账号。
- 验收硬标准：**自愈重读前后，账号身份（user_id）必须不变**；变了就是 bug。

### 3. 账号库交互语义（补强 D3/D3a）
- 捕获即入库，但**不自动切换**当前账号；列表里点「切换」才生效（下一轮请求用新号）。
- 探活失败的账号标红「需要重新登录」，行内给「重登此账号」按钮（不清分区，
  与「添加新账号」的清分区语义严格分开）。
- 失效拦截只认**授权类**失败（401/403 NEED_LOGIN/LOGIN_INVALID）；
  断网、超时、边缘 404、5xx、429 一律不拦（probeAuth 已有此意识，保持）。
- 去重：按 `oneday_sid` + user_id 判同一账号，重复捕获原地更新不新增。

## 三、明确不搬的部分（防止新赘余）

PoW 求解、提示词工具协议、链式上下文投喂、随机节流闸门、长休/滚动窗口限速、
会话攒批清理、自动换号 —— 全是 DeepSeek 风控场景产物。秒悟是积分制、未见频控，
且我们复用项目不建删会话，没有对应问题。**一律不搬。**

CDP 页面内 fetch 传输层（browser-transport.ts 模式）仅作 D5 后手：
T3 已实证无输出根因是解析层两个 bug（data.data.delta 层级漂移 + finish_reason
提前掐流），T4 照裁决修解析层即可，**不动传输层**。仅当 T4 修后仍有
「start 200 但流里零帧/风控空流」证据时，才另立任务上 CDP 传输。
届时两个现成的坑直接避开：
- 页面 fetch 的禁止头（cookie/origin/referer/host…）会被浏览器静默丢，
  cookie 必须走 CDP `Network.setCookie`，页面必须站在 meoo.com origin；
- `accept-encoding` 不能收进复用头（服务端可能回 zstd，Node 解不开会静默乱码）。

## 五、与全局浏览器规则的关系

用户全局规则「会话里只用 browser_*、不开临时 profile」约束的是 **agent 干活用的
浏览器**；本设计是**插件产品运行时**给最终用户开的登录窗（不碰用户日常 Chrome 的
cookie 与历史），两者不冲突。降级方案（若用户日后要求插件也不开独立窗口）：
保留抄录路径，按 `oneday_sid` 绑定账号身份、抄到不同身份拒绝覆盖。
