# dsh-get-it-for-free

[![release](https://img.shields.io/github/v/release/hulibuld/dsh-get-it-for-free)](https://github.com/hulibuld/dsh-get-it-for-free/releases)
[![DSH](https://img.shields.io/badge/DSH-0.2.x-blue)](https://github.com/hulibuld/dsh-get-it-for-free)
[![License](https://img.shields.io/badge/license-MIT-blue)](LICENSE)

[遇到问题开 issue](https://github.com/hulibuld/dsh-get-it-for-free/issues/new/choose)

把免费、签到型的大模型账号渠道接进 DeepSeek。设置里登录账号、每日签到、同步可用模型池，模型以普通 provider 的形式出现在模型选择器里。

纯本地运行，没有遥测，不向上游仓库发请求。账号凭据只写在本机 `~/.dsh/get-it-for-free/`。

## 装

插件按 profile 方式装。把插件目录放进 profile 的 `node_modules`，在 `package.json` 的 `dsh.profile.bundles` 里加 `dsh-get-it-for-free`，重启 DSH。`cordis.patch.yml` 由 bundle 层自动合并，不用手改。

从 npm 装（推荐）：

```
cd ~/.dsh/profiles/desktop
pnpm add dsh-get-it-for-free
```

用 tarball 的话：

```
cd ~/.dsh/profiles/desktop
pnpm add file:/path/to/dsh-get-it-for-free-<版本>.tgz
```

然后同样在 `dsh.profile.bundles` 里加名字。装完重启 DSH，界面部分刷新页面即可。要 Node.js `^22.19.0 || >=24.0.0`，DSH `0.2.0-rc.1` 及以上。

## 能做什么

账号看板一页管完各渠道账号，登录、刷新、退出、启停，登录态存在本机。

每日签到，支持的渠道可以手动点，也可以开自动。每天 10:05 还会补跑一轮，因为 Qoder 的每日活动要等到 10:00 才刷新，早上开机那轮看到的是昨天的。这一轮同时补上宿主一直开着不重启、跨过零点之后第二天不签的缺口。

Qoder 报「领取未成功，status=BLOCKED」不一定是真失败。它有时先受理、稍后下发积分，插件会先重看一次活动列表，确认到 CLAIMED 就按成功记账，确认不到才报出来，交给后台下一轮再确认。

模型池定时探测每个账号当前可用的模型，按可用和区域受限两档注册成 provider。每天 12:00 强制各渠道重新拉一次远端目录，因为渠道平时把目录缓存在进程里，不重启看不到上游新上的模型。到点没开机，下次启动立刻补刷，失败不会记成成功。

这一轮不只是清缓存，还会把每个渠道的目录真拉一遍，和上一份快照比出**新增、下线、能力变更**，结果写在设置页的「模型同步」卡片上，也可以点「立即同步」手动跑。看到 `+3 −1` 就知道这一轮上游动了什么，不用去猜选择器里为什么少了一条。快照存在 `~/.dsh/get-it-for-free/model-sync.json`，留最近 40 轮历史。它只读目录，不碰你自己关掉的模型开关。

单个渠道拉不动不会拖垮整轮：每个渠道 25 秒硬超时，失败只记一行原因，其余照常写入；某个渠道这次返回空目录时沿用上一份快照，不会把整批模型误判成「新增」。

模型开关按渠道分，能单独关也能一键全关。一条账号都没有的渠道，模型会自动全关掉，列表里不会挂着用不了的开关。

用量看板在本机统计 token 与调用次数，按渠道、按模型分列。

MiMo 桌面端额度不添加账号，直接复用小米桌面端已登录的 cookie，设置页显示剩余额度与重置日期。

CodeBuddy CLI 通道是可选的第二条路。它不自己拼 HTTP 请求，改成调用你自己装好、自己登录的 `codebuddy` CLI，发出去的流量和普通 CLI 用户一样。每轮要启一次进程、正文整段落地，所以它和 HTTP 通道并存，在选择器里单独一组。没装 CLI 时这组不出现。

设置页里还有一张「本机 API 网关」卡片，把上面所有渠道合成**一个 OpenAI 兼容的入口**：`base_url` 是 `http://127.0.0.1:8326/v1`，`api_key` 只有一把，第一次打开这张卡就自动生成（文件在 `~/.dsh/openai-gateway/api-key`，权限 0600）。`/v1/models`、`/v1/chat/completions`、`/v1/responses` 三条路由都在，任何认 OpenAI 协议的客户端都能直接用。卡上有「复制 base_url + Key」，粘到别处就配好了；还有一个「自检」，当场验证端口通不通、错 key 会不会被挡。开关关着时不会监听 8326，key 照样能看能复制。

多个腾讯账号各算各的。插件给每个账号单独传自己的令牌，不共用本机那份。选择器里只列模型名，不写账号名，请求在它们之间轮流走。老会话里 `hy3@账号 id` 的写法仍然有效。

思考强度按模型的档位传，在模型选择器里选档位即可。

大上下文不再被截断。CLI 的返回改成先落临时文件再读回，之前接管道时进程退出太早，超过 64KB 的返回必然半截。

长回答不会被误杀。原来 4 分钟的总时限会杀掉一个其实正在成功的请求，现在总时限放宽到 15 分钟，判据改成沉默，连续 5 分钟没有任何输出才判卡死。

思考过程看得见。CLI 通道改成流式输出，边想边显示；正文仍以结构化结果为准，不会出现两份答案。

CLI 三分钟不出字就直说。有一次模型在正文里要求调用 bash，而 CLI 只给了结构化输出工具，于是它反复重试同一份上下文，七分钟一个字节都没写出来。现在第一个字节单独计时，三分钟没有任何输出就直接失败并说明原因。

失败不再是一句话。CLI 失败会给出具体原因，登录失效、模型不可用、服务端 5xx、轮次用尽、网络，瞬时故障自动重试一次，原始输出追加写进本机日志。设置页卡片上有「自检一次」，跑一个最小请求，几秒内告诉你现在通不通。

腾讯 HTTP 通道的风控指纹在发请求前逐字替换。上游靠提示词指纹判定不是官方客户端，命中就回 400。已知两处，一是 `DeepSeek` 这个词组，二是那两行路径说明，都改成同义句，意思不变。

测试按钮不藏起来，账号区默认展开，测试失败也会写明原因。商汤 Raccoon 与 Loomy 之前被当成华为云去探活，永远测不过，现在各走各的适配器。

CodeArts 的临时令牌大约两小时一换。以前面板上的余额、签到状态、一键领取直接拿存储里的凭据去请求，宿主刚启动就打开设置页时，正好撞上还没换掉的旧令牌，两个账号一起报 `APIG.0602 the security token has expired`。现在这三条读接口发请求前会先按需续期，真撞上过期就强制续期并原样重发一次。账号行的「续期」也改成真的换一份新令牌，不再因为「还剩一小时」而什么都不做。

商汤（Raccoon）网页版每天能领 300 积分，插件也能领了。这笔积分不是定时发的：服务端在账号当天第一次以网页客户端身份访问办公接口时才落库，账单里 `client_type` 写的是 `web`。所以「一键领取」先查当天账单，没有就模仿网页端的请求头发几条只读办公接口，隔一会儿再看账单确认到账；已经发过的直接说「今日积分已经发过了」。账号行显示「今日已领 300」，每日自动签到也会把这一笔领掉。还没领过的一次性桌面端登录奖励（3000 积分）在同一个按钮里顺带领。

## 配置

设置页能改，也可以直接改 `~/.dsh/get-it-for-free/settings.json`。

| 键 | 含义 |
| --- | --- |
| `enabled` | 总开关，关掉后本插件的模型不再出服务 |
| `hideAllModels` | 一键隐藏本插件注册的全部模型 |
| `hiddenModelIds` | 单独隐藏的模型 id |
| `hideFreeModels` / `hideEacModels` | 按来源分组隐藏 |
| `probeIntervalMinutes` | 模型目录探测周期，默认 15 分钟 |
| `autoReloadWatch` | 改插件目录后自动热重载 |

## 隐私

仓库里不含个人信息、本机路径、账号凭据或推广链接。

运行期的登录态和缓存只在本机数据目录，不会上传。升级时会自动迁移旧数据目录一次。

`vendor/channel-pack/` 里的第三方代码保留各自原许可证，见同目录的 `NOTICE.md`。
